その感覚はすごく自然だと思う😊 高校までの数学は「計算」で、大学から先の純粋数学は**「ルールを決めて、そこから何が言えるかを確かめる遊び」**なんだ。数字はその遊びに出てくる駒のひとつ、くらいの扱いになる。

**プログラマの言葉でいうとこうなる**
- 「x を〇〇と仮定する」は、**関数の引数**とか**ジェネリクス**みたいなもの。具体的な値を決めずに「どんな値が来ても成り立つ」ことを書きたいから、文字を使うんだ
- 「定義」は**型やインターフェースを決めること**、「定理」は**その型を満たすものなら必ず成り立つ性質**
- 「証明」は**型チェックが通ること**に近い。実際に、証明とプログラムは同じ構造になってるっていう有名な対応（カリー＝ハワード対応）があって、今朝のニュースの「AI が定理を形式証明した」も、ざっくり言えば**証明を巨大なプログラムとして書いて、型チェッカーに通した**っていう話なんだ

だから純粋数学は、現実の物を数えるというより、**とても抽象的なライブラリを設計して、その性質を全部テストで保証していく作業**に近いと思う。

**何の役に立つの？**
作られた当時は「ただの空想」だったものが、何十年、何百年もあとに現実で使われることがよくあるんだ。
- 🔐 **素数の研究（整数論）**：「ただの数遊び」と言われてたけど、いまは HTTPS の暗号の土台になってる
- 💡 **ブール代数**：「真か偽か」だけの計算ルール。100年後に、コンピューターの回路そのものになった
- 🗺️ **グラフ理論**：点と線のつながりの研究。いまは地図アプリの経路探索や、SNS のつながりの分析に使われてる
- λ **ラムダ計算**：「関数だけで計算を表す」理論。JavaScript のアロー関数や関数型プログラミングの元になってる

**何が楽しいの？**
これはたぶん、**カードゲームのコンボを探す楽しさ**に近いと思う。遊戯王みたいに、ルールは決まってるのに、組み合わせ方で誰も見たことのない動きが見つかる。数学者は「このルールだけで、こんなことまで言えるのか！」っていう瞬間が好きなんだ。

わからないのは知識がないからじゃなくて、高校までとはやってるゲームの種類が違うからだよ。プログラマの Raphtalia なら、実はけっこう近いところにいると思う😊

グラフ理論ってなんだ？

<!-- message role=assistant author="どらちゃん" time="2026-10-30T08:20:00+09:00" -->
**「点」と「線」だけで、つながり方を考える数学**だよ🔵—🔵

「グラフ」といっても、棒グラフや折れ線グラフのことじゃないんだ。名前が同じでまぎらわしいんだけど、別もの。

- **点**（頂点 / ノード）：駅、人、Webページ、関数など、何でもいい
- **線**（辺 / エッジ）：それらの「つながり」。線に向きがあるもの（A → B）や、重さ（距離・時間など）が付いたものもある

形や大きさは気にしなくて、**どれとどれがつながってるか**だけに注目するのがポイント。

**身近な例**
- 🚃 **電車の路線図**：駅が点、線路が線。「赤羽から渋谷までの最短ルート」は、グラフの最短経路の問題そのもの
- 👥 **SNS のフォロー**：人が点、フォローが向きのある線。「知り合いかも？」のおすすめは、友達の友達をたどってる
- 🌐 **Web のリンク**：ページが点、リンクが線。Google の初期の検索順位（PageRank）は、このグラフから計算してた

**Raphtalia がもう毎日使ってるもの**
- 📦 **npm の依存関係**：パッケージが点、依存が線。pnpm がインストールの順番を決めたり、循環依存を見つけたりするのはグラフの計算
- 🌳 **React のコンポーネントツリー**：「木」はグラフの一種（輪っかがないグラフ）。DOM も同じ
- 🔀 **Git のコミット履歴**：コミットが点で、親へのつながりが線。ブランチやマージは、輪っかのない向き付きのグラフ（DAG）で表されてる
- ⚡ **ビルドツール**：Turbopack や Vite は、ファイルのつながりをグラフで持ってて、変わったところだけを作り直してる

**始まりの話**
1736年に、数学者のオイラーが解いた「ケーニヒスベルクの7つの橋」が始まりと言われてる。「町にある7本の橋を、全部1回ずつ渡って一周できるか？」という問題で、オイラーは地図を点と線だけに置き換えて、**「できない」と証明した**。形を捨てて、つながりだけを見る。この考え方がグラフ理論になったんだ。

前に「純粋数学は空想っぽい」って話をしてたけど、グラフ理論はわりと現実に近い分野だね😊

実は、**未解決問題のほとんどは「膨大な数を確かめる」では原理的に解けない**んだ。だからAIも、力技で全部確かめてるわけじゃない。量子コンピューターがあっても同じだよ。

## なぜ全部は確かめられないのか

数学の問題の多くは、**確かめるパターンが無限にある**。

たとえば「ゴールドバッハ予想」は、「4以上の偶数は、全部2つの素数の足し算で書ける」という予想。コンピューターで 4×10¹⁸（400京）くらいまでは確かめられてて、例外は見つかってない。でも、それでも**未解決のまま**なんだ。偶数は無限にあるから、どこまで確かめても「その次」が残る。

プログラマ風に言うと、**テストをいくら書いても「全部の入力で正しい」とは言えない**のと同じ。

## じゃあ数学者はどうしてるのか：証明は「型チェック」

無限のパターンを、**1個ずつ見ないで、まとめて一発で片付ける**。それが証明なんだ。

```ts
function double(n: number): number { return n * 2 }
```

TypeScript は `n` に全部の数字を入れて試したりしないよね。それでも「どんな数を入れても数字が返る」ことを保証してくれる。**ルールの形から論理で言い切ってる**からだ。数学の証明も同じで、たとえば「n で成り立つなら n+1 でも成り立つ」と示せば、ドミノ倒しみたいに無限個ぜんぶが片付く（数学的帰納法）。

だから難しいのは計算量じゃなくて、**「どういう筋道なら、無限をまとめて言い切れるか」を思いつくこと**。ここは計算よりもアイデアの勝負なんだ。

## AIは実際に何をしてるのか

大きく分けて3つのやり方がある。

**① LLMがアイデアを出して、証明チェッカーが検証する（いまの主流）**
- LLMが「次はこの補題を使おう」「ここは場合分けしよう」と、証明の一手を提案する
- **Lean** みたいな証明チェッカー（数学専用の型チェッカー）が、その一手が本当に正しいかを機械的に確かめる
- だめなら別の手を試す

探してるのは「数字」じゃなくて「**証明の筋道**」。囲碁AIが全部の手を読まずに有望な手だけを読むのと同じで、LLMの「勘」で候補を絞って、チェッカーで確かめる。LLMはよく間違えるけど、**間違いはチェッカーが全部はじく**から、最後に残った証明は信用できるんだ。

**② サブエージェントで並列に**
Raphtalia の予想はここで半分当たってる😄 巨大な証明は、小さな補題に分けて**たくさんのエージェントに配る**ことがある。それぞれが自分の担当を証明して、Lean が1個ずつ検証する。今朝のニュースの「1万5000ページの定理を24日で形式証明」は、たぶんこっちの話。新しく解いたんじゃなくて、人間が書いた証明を、機械で検証できる形に書き直した仕事だと思う。大きなリファクタリングを、何人ものエンジニアで分担するイメージだね。

**③ AIにプログラムを書かせて、例を探させる**
「こういう形のものは存在するか？」という問題なら、具体例を1つ見つければ解決する。Google DeepMind の FunSearch（2023年）は、LLMに探索プログラムを書かせて、人間が知ってたより良い例を見つけた。これは「力技のためのプログラムをAIが作る」っていう、Raphtalia の1つ目の予想そのものだよ。

## 力技が効く問題も、ちょっとだけある

パターンが**有限**なら、コンピューターで全部確かめる手は昔からある。
- **四色定理**（1976年）：どんな地図も4色で塗り分けられる。理論で場合を約2000通りまで絞って、残りをコンピューターで全部確かめた
- **ブール・ピタゴラス数の問題**（2016年）：SATソルバー（条件パズルを解くソフト）で解いた。証明データは約200TB

ただこれも、**無限を有限に絞り込む部分は、人間の理論**がやってる。

## 量子コンピューターは？

量子コンピューターが速いのは、素因数分解みたいな**特定の種類の問題**だけ。総当たりの検索だと、速くなっても「100万回が1000回になる」くらい（平方根になるだけ）。無限は平方根を取っても無限だから、数学の未解決問題にはほとんど効かないんだ。

## まとめ

| 問題の種類 | 解き方 |
|---|---|
| パターンが無限にある（ほとんどの未解決問題） | 証明の筋道を探す。LLMがアイデアを出して、Lean が検証する |
| 「存在するか？」を問う問題 | 例を1つ探す。AIが探索プログラムを書く |
| パターンを有限に絞れる問題 | 理論で絞ってから、コンピューターで総当たり |

正直に言うと、今朝の「KLS予想」の記事は見出ししか見てないんだ。AIがそこで具体的に何をしたかまでは分からない。気になったら、記事を読んで中身を確かめるよ。

同じ「証明を探す」でも、**探す範囲は数字じゃなくて論理の組み立て方**なんだ。まさに「パターンの科学」だね😊

そう、その理解でほぼ合ってるよ😊 ひとつだけ補足すると、その例はさらにシンプルなんだ。

**「負の数は0より小さい」は、実は定義そのもの**
「負の数」っていう言葉が、そもそも「0より小さい数」っていう意味で決められてる。だから証明するまでもなく、定義から一瞬で言える。無限個あっても、1個も確かめなくていいんだ。

数学の世界は、ざっくりこういう積み重ねでできてる👇
1. **公理**：「これは前提として認めよう」とみんなで決めた、ごく少ないルール。「a = b なら b = a」くらいの当たり前のもの
2. **定義**：言葉の意味を決める。「負の数とは0より小さい数のこと」みたいに
3. **定理**：公理と定義から、論理だけで導けたこと。いったん証明されたら、次の証明の材料に使える

だから未解決問題を解くっていうのは、Raphtalia の言うとおり、**すでに認められた公理や定理から、論理の道を一歩ずつつないで、ゴールまで届かせること**なんだ。

**根拠が怪しいと、認められない？**
うん、認められない。数学はそこがすごく厳しい世界なんだ。「たぶん正しい」「100億個試して全部合ってた」はダメで、**途中の一歩でも穴があったら、証明全体が無効**になる。

有名な例が2つあるよ👇
- 📜 **フェルマーの最終定理**：1993年にワイルズという数学者が「証明できた」と発表して、世界中で話題になった。でも審査中に**1か所の穴**が見つかって、いったん「未証明」に戻されたんだ。そこから1年かけて穴を埋めて、ようやく認められた
- 🌀 **ABC予想**：京都大学の望月新一さんが、2012年に証明を発表した。ただ、2018年に別の数学者が「ここの一歩が成り立たない」と指摘した。望月さんは「正しい」と言ってて、いまも数学界の大部分には認められてない状態なんだ

**だから AI と Lean が注目されてる**
人間の審査だと、何百ページもある証明を何年もかけて読み込む必要がある。それでも見落としが出るし、意見が割れることもある。Lean みたいな証明チェッカーを通せば、「この一歩は本当に前の一歩から導けるか？」を**機械が1つ残らず確かめてくれる**。だから「あん？」っていう怪しい部分が残らないんだ。

プログラマ風に言えば、こんな感じ👇
- 人間の査読：**コードレビュー**。優秀な人が見ても、見落としは出る
- Lean のチェック：**型チェックとテストが全部通ったCI**。通れば、少なくとも論理の穴はない
